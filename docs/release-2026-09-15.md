# 2026年9月15日版本说明

版本号：2026.9.15。对应《小程序使用感想及修改建议》的四项要求。

## 用户可见变化

1. 按识别食材名称判断肉类，最终估重及上下限统一乘 0.5；不按整道菜的类别打折，肉菜中的土豆、青椒等维持原算法。排除鱼虾、蛋、素肉、鸡腿菇等易误判名称。
2. 结果页和记录详情隐藏估重依据、匹配菜名、匹配解释和源文件名。保留估重、区间、软硬与九项质构数据及参考说明。
3. 结果和详情底部增加“饭后评估”。每种食材支持 0%–500%，100% 代表拍照份量全部吃完，500% 代表食用了拍照份量的五倍。逐项调整或点选才视为已确认；未确认时不允许完成评估。
4. 结果、详情和评估页食材右上角均可删除。删除后更新总重、历史摘要和评估摄入；原始模型结果仍保留供追溯。全部删除时完成这餐，避免阻塞下一餐。

## 保存与重新进入

- 新版创建任务时设置 `evaluationStatus: pending`；识别完成后仍为待评，只有提交成功或清空食材才变为 `completed`。
- 首页、拍照入口与创建任务的 service 均检查待评记录。取消提醒只能稍后评估，不能跳过上一餐开始下一餐。
- 从后台回到结果或历史页时提醒未完成评估；返回饭后评估页会恢复已填写比例。
- 滑动后的草稿先保存本机，再按顺序同步云端，避免旧请求覆盖新比例。同步失败时保留本地草稿并明确提示；“完成评估”必须等云端保存成功才能解除待评状态。
- 没有 `evaluationStatus` 的旧版记录不强制补评；识别失败的任务不阻塞下一餐。

## 2026-09-22 增补

- 首页和上传页要求填写参与者编码；编码保留前导零，保存到本机并作为每条识别记录的快照。
- 结果、待评估和详情页提供「我要重新拍照」。确认后将记录标为 `status: discarded` / `evaluationStatus: discarded`，清理本地评估草稿并回到上传页；作废记录不进入历史，也不会阻挡下一餐。

## 后台查看与导出

现已提供可重复使用的导出工程，按 [识别数据导出手册](./data-export.md) 运行 `npm run export:data` 或 `npm run export:cloud`。以下字段由工具展开为CSV，不需手工整理嵌套食材。

云开发控制台的 `meal_records` 集合保留以下字段，可直接查看或随数据库导出：

| 字段 | 含义 |
| --- | --- |
| `result.dish` | 识别菜品及前端估重输入；新模型含云端份量校准，原始几何量见 `modelAudit.rawDish` |
| `participantCode` | 本次识别使用的参与者编码快照 |
| `status` / `discardedAt` | 识别状态及作废时间；作废记录保留原始结果供后台追溯 |
| `excludedIngredients` | 用户删除的食材名 |
| `evaluationStatus` | 饭后评估待完成或已完成 |
| `consumption.percentages` | 食材名对应食用百分比 |
| `consumption.consumedGrams` | 食材名对应估算摄入克数 |
| `consumption.totalConsumedG` | 这一餐的估算摄入总重 |
| `consumption.completedAt` | 完成评估的时间戳 |
| `auditSnapshot.algorithmVersion` | 估重算法版本 `2026-09-15-meat-half` |
| `auditSnapshot.ingredients` | 每项估重、区间、估重依据、排除标记、匹配记录 ID、菜名、食材名、烹饪方式、匹配原因、切割/下压测试来源 |

审计快照在打开结果/详情、改选、删除或保存评估时更新，记录当时算法的结果。旧记录首次打开新版后生成快照；未打开的旧记录不做批量改写。

## 提审说明

小程序用于菜品拍照识别、食材重量估算及饮食记录。测试路径：首页 → 开始拍照识别 → 拍照或相册选择菜品照片 → 选择餐盘直径 → 开始识别 → 查看各食材估重和质构参考 → 删除误识别食材（可选）→ 饭后评估 → 逐项滑动或点选食用比例 → 完成评估。

无需测试账号。先填写参与者编码，再拍照识别。识别结果不合适可点「我要重新拍照」直接作废并重拍，无需先估重；保留结果时仍需完成饭后评估。0% 为没有食用，100% 为拍照份量全部吃完，超过 100% 表示添菜。结果为图像估算及同类食材样本实测参考，不是对用户食物的实际称重或医学建议。

## 设计审查与处理

| 原有问题 | 本次处理 |
| --- | --- |
| 首页两个开始按钮执行同一件事，介绍文字占据大块首屏 | 合并为一个拍照主入口，编号紧邻操作；饮食记录、每周随访分为两张入口卡；使用说明可展开 |
| 卡片、按钮、图标和字号缺少统一层级 | 米白底色、深青绿主色、柔和草绿与暖米色辅助色；统一圆角、间距、阴影和线性图标；本地 SVG 餐盘插画 |
| 拍照、餐盘尺寸与参与者信息缺少顺序提示 | 按「确认参与者 → 拍摄菜品 → 选择餐盘直径」分步排版，底部固定开始识别操作；照片保持原始比例并支持预览 |
| 等待页只有转圈，进度与步骤联系较弱 | 餐盘扫描动效、进度条平滑变化、步骤完成／进行中／等待状态；进度仍采用服务返回值 |
| 结果、详情页长内容难以定位，实验指标过密 | 菜名、原图、原参与者编号、总体摘要优先；九项指标按食材折叠；匹配备选显示已选；重拍入口放在菜品信息内 |
| 主操作必须滚到长页面底部 | 拍照、结果、详情、饭后评估使用适配底部安全区的固定操作区，并给内容预留滚动空间 |
| 历史加载失败被表现成空列表，没有快捷筛选 | 区分加载、错误重试、空记录与无搜索结果；增加编号／菜名／食材搜索、待评估／已评估筛选、下拉刷新 |
| 历史列表宽度紧张，长编号挤压菜名 | 编号独立成行，完整保留前导零与最长 32 字符；图片、菜名、日期和状态分别排版 |
| 评估默认 100% 容易被误认为已确认 | 未操作时显式显示「待确认」；常用比例优先展示，0／50／100% 附「没吃／一半／吃完」；确认状态与摄入量同步更新 |
| 随访问卷选项和保存反馈层次不够明确 | 加强选项勾选、题目状态、进度条、漏答提示、提交成功和记录空状态，保留原题目与答案规则 |

历史搜索与筛选作用于当前接口返回的最近 30 条识别记录，页面明确显示此范围；本次未扩展云端分页。

## 实现与动效

- `miniprogram/app.wxss` 定义共享配色、文字、按钮、卡片、输入、空状态、加载与底部操作区。
- `miniprogram/styles/meal.wxss` 统一结果、详情和饭后评估的食材展示，替代页面之间的样式互相引用。
- `miniprogram/assets/` 存放本地 SVG 插画及图标，无远程字体或新增运行时依赖。
- 动效使用 CSS：首屏短暂淡入、餐盘轻浮动、识别扫描与步骤脉冲、选中反馈、进度过渡。装饰浮动只运行两轮；支持 `prefers-reduced-motion`，不依赖动画传达状态。
- 主要操作使用原生 `button`，保留禁用与加载状态；编号、搜索、比例及图片预览提供可读标签。
- 加载失败可以重试；后台数据失败时不再将空字段当成正常结果展示。
- 评估保存队列改为在页面加载时初始化，避免开发者工具克隆 Promise 的警告；文字选择使用当前基础库建议的 `user-select` 属性。

# 发布上线 与 更换 API Key

面向「改完代码之后我该点哪些按钮」的操作手册。两件事互相独立：

- **换 API Key** 只改云端的一个环境变量，代码不用动，小程序也不用重新发版；
- **发布新版本** 要走「开发者工具上传 → 微信公众平台提交审核 → 发布」。

---

## 一、先把云端准备好（只需做一次）

在**微信开发者工具**里打开本项目（目录选仓库根目录，含 `project.config.json`）。

### 1. 部署云函数

1. 左侧「资源管理器」找到 `cloudfunctions/analyzeMeal`；
2. **右键该文件夹 → 上传并部署：云端安装依赖（不上传 node_modules）**；
3. 等待右下角提示「上传成功」。

> 只要改过 `cloudfunctions/analyzeMeal/index.js`，就要重新执行这一步，
> 否则云端跑的还是旧代码。小程序页面（`miniprogram/` 下的内容）不走这一步。

### 2. 配置云函数环境变量与超时

1. 工具栏点「云开发」打开云开发控制台；
2. 左侧「云函数」→ 找到 `analyzeMeal` → 点函数名进入；
3. 「版本与配置」标签页：
   - **超时时间** 改为 `60` 秒（视觉模型较慢，默认 3 秒一定会失败）；
   - **环境变量** 添加一条：键 `DASHSCOPE_API_KEY`，值填你的千问 API Key；
4. 点「保存」。

### 3. 数据库与云存储

1. 云开发控制台 →「数据库」→ 新建集合 `meal_records`；
2. 该集合「权限设置」选 **仅创建者可读写**；
3. 「存储」标签确认已开通即可（照片会存在 `meal-images/` 前缀下）。

### 4. 确认前端开关

`miniprogram/services/config.ts` 里 `useCloud: true`（走真实云端）。
改成 `false` 会整条链路回落到本地假数据，用于没网/没配 Key 时演示。

## 二、更换 API Key（最常用）

**正常情况下只需要改一个环境变量，不用改代码、不用重新上传小程序。**

> 当前 Key（2026-08-28 更新）保存在仓库根目录的 `.env` 里（该文件已被 `.gitignore` 忽略，
> 不会进仓库）。云端不会自动读这个文件——它只是本地留底，方便你复制粘贴到下面第 4 步。

1. 微信开发者工具 → 工具栏「**云开发**」；
2. 左侧「**云函数**」→ 点 `analyzeMeal`；
3. 打开「**版本与配置**」标签页；
4. 找到「**环境变量**」一栏，把 `DASHSCOPE_API_KEY` 的值换成新的 Key；
5. 点「**保存**」。保存后新调用即刻生效（可能有几秒的实例回收延迟）。

也可以在浏览器里操作：登录 [腾讯云开发控制台](https://console.cloud.tencent.com/tcb)
→ 选环境 `cloud1-d8gfgeids7d390dbc` → 云函数 → `analyzeMeal` → 函数配置 → 编辑 → 环境变量。

### 验证新 Key 是否生效

1. 开发者工具里跑一次「拍照 → 识别」；
2. 若结果页正常出菜名，说明 Key 可用；
3. 若一直转圈后提示「识别失败」，去云开发控制台 →「云函数」→ `analyzeMeal` →
   「日志」看报错：
   - `未配置 DASHSCOPE_API_KEY 环境变量` → 变量名拼错或没保存；
   - `401` / `InvalidApiKey` → Key 不对、被禁用或没开通 qwen-vl 权限；
   - `Arrearage` / `欠费` → 阿里云百炼账户余额不足；
   - 超时 → 函数超时时间没调到 60 秒。

### 换成别家的模型怎么办

如果新 Key 不是阿里云百炼（DashScope）的，光换环境变量不够，还要改
`cloudfunctions/analyzeMeal/index.js` 顶部这两行，然后重新部署云函数：

```js
const DASHSCOPE_URL = 'https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions';
const MODEL = 'qwen-vl-max';
```

它用的是 OpenAI 兼容的 `/chat/completions` 协议，换成同样兼容该协议的多模态服务
只需改这两个常量 + 环境变量名。

> **安全底线**：Key 只能待在云函数环境变量里。永远不要写进 `miniprogram/` 下的任何
> 文件、不要写进 `config.ts`、不要提交进仓库——小程序代码包是会下发到用户手机上的。

## 三、发布新版本到微信公众平台

### 第 1 步：本地自检

```bash
npm run type-check      # 应无任何报错
```

在开发者工具里点「编译」，把首页 → 拍照 → 识别 → 结果 → 历史 → 详情整条流程点一遍。

### 第 2 步：上传代码（开发者工具）

1. 确认右上角登录的是**有该小程序权限的微信号**；
2. 点工具栏右上角「**上传**」；
3. 填写：
   - **版本号**：如 `2.0.0`（本次是去掉重量、改为质构匹配的大改动）；
   - **项目备注**：如「改为菜品质构数据匹配，移除重量估算」；
4. 确认后等待上传完成。

> 上传的是 `miniprogram/` 这一整包（含 131 KB 的质构数据库），远低于 2 MB 主包上限。
> 云函数不随这一步上传，云函数改动必须单独执行前面的「上传并部署」。

### 第 3 步：在微信公众平台设为体验版并提审

1. 浏览器打开 [mp.weixin.qq.com](https://mp.weixin.qq.com) 并登录小程序账号；
2. 左侧「**管理 → 版本管理**」；
3. 在「**开发版本**」里找到刚上传的那条：
   - 点「**选为体验版**」→ 生成体验二维码，先让老人用的那台手机扫码实测；
   - 确认没问题后点「**提交审核**」；
4. 提交审核时要填：
   - **功能页面**：把 `pages/index/index` 等页面选上；
   - **测试帐号/测试说明**：写清楚「上传一张菜品照片即可看到识别与质构结果」，
     最好附一两张示例菜品照片，审核员看不到实物；
   - **类目**：本小程序属于工具 / 健康信息查询类，注意**不要**在文案里出现
     「诊断」「治疗」「医学建议」等字眼，页面上的免责声明保持原样别删。
5. 审核一般 1–3 个工作日。通过后回到「版本管理 → 审核版本」点「**发布**」，
   全量用户才会用到新版本。

### 第 4 步：发布后确认

用正式版扫码进入，重新跑一次拍照识别；顺便去云开发控制台看一眼云函数调用次数
和错误率是否正常。

## 四、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 一直转圈，90 秒后提示超时 | 云函数超时没设 60s，或 Key 无效 | 看云函数日志，按上面第二节排查 |
| 提示「识别失败」 | 千问返回非 JSON / 图片拉取失败 | 云函数日志里看 `[analyzeMeal] process failed` 后面的原因 |
| 结果页菜名对但质构数据明显不对 | 库里没有这道菜，走的是食材相似匹配 | 点「不像？换一个」从备选里改，或搜索关键词自选 |
| 改了云函数没生效 | 只点了「上传」小程序，没重新部署云函数 | 右键 `cloudfunctions/analyzeMeal` 重新「上传并部署」 |
| 改了质构 xlsx 没生效 | 忘了重新编译数据库 | `python3 scripts/build-texture-db.py` 后重新上传小程序 |

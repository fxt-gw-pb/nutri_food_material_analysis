# 2026.11.28 更新说明：二维码尺寸参照卡、按餐分层的饮食记录、饭后评估输入

## 1. 二维码卡片作尺寸参照（不选餐盘也能估重）

**怎么用**：打印 [交付/二维码尺寸参照卡-4x4cm-A4.pdf](../交付/二维码尺寸参照卡-4x4cm-A4.pdf)，打印时选「实际大小 / 100%」，不要选「适合页面」。打印后用尺子量：黑色外框边长应为 4.0 cm，页首校准线应为 4.0 cm。沿虚线剪下（建议塑封）。拍照时把卡片平放在餐盘旁边，和餐盘一起整张拍进去。

**上传页**：第 3 步改为「尺寸参照」，两种方式二选一：
- **用二维码卡片（默认、推荐）**：不用选盘子大小；
- **选择餐盘直径**：手边没有卡片时用，与以前完全相同。

手机会记住上次选的方式。

**识别怎么做**：卡片模式下，云函数用新提示词 `qwen-dish-visible-food-weight-v8-qrcard-v1`。它在 v8 基础上只改了三处：以 4 cm 卡片为尺度、先量出餐盘（或碗）口径、多输出 `plateDiameterCm` 和 `referenceCardVisible`。其余约束逐字不变；面积比例、厚度、直接估重仍按原定义输出，份量校准（系数 1.9）和本地估重公式也不变。模型量出的盘径（10–60 cm 之外视为无效、要求重答）写回记录，作为这道菜的估重尺度。

**选餐盘直径时**：提示词与 v8 逐字相同，旧版前端发来的请求也照旧处理，已有数据口径不受影响（有测试锁定）。

**新字段（`meal_records`）**：

| 字段 | 含义 |
| --- | --- |
| `scaleMode` | `plate` 用户选盘径 / `qr-card` 二维码卡片 |
| `plateDiameterSource` | `user` 用户选的 / `qr-card` 对照卡片量出 / `model-guess` 照片里没看到卡片、模型按常见餐具粗估 |
| `referenceCardVisible` | 卡片模式下模型是否看到了卡片 |
| `referenceCardCm` | 卡片边长，固定为 4 |
| `modelAudit.scaleEstimate` | 模型原始的盘径估计 |

导出的 `meals.csv` 新增 `plate_diameter_source` 列；`prompt_version` 也能区分两种模式。结果页和详情页的估重说明会写「按二维码卡片量出餐盘约 23cm 估算」；没看到卡片时写「按餐盘约 26cm 粗略估算」。

> **数据口径提醒**：份量校准系数 1.9 是在「用户选盘径 + v8 提示词」下拟合的，**没有在卡片模式下重新验证**。卡片模式的估重应视为新口径。正式统计前，建议用几道称过重的菜分别用两种方式拍一次，对比后再决定是否需要单独校准；分析时可按 `plate_diameter_source` 分组。

**上线前必须重新部署云函数 `analyzeMeal`**。旧云函数不认识卡片模式，会悄悄按 26 cm 盘子估重。

## 2. 饮食记录按「哪一天 → 哪一餐 → 哪道菜」分层

- **饮食记录页**：按日期分组（最新的一天在上，标「今天 / 昨天」）。每天里按早餐、早加餐、午餐……排列，每一餐一张卡片，显示缩略图、菜名、参与者编号、几道菜、几道待评估。搜索和「全部 / 待评估 / 已评估」筛选照旧，一餐里只要有一道菜符合条件就显示这一餐。列表最多取最近 60 道菜（以前实际只有 20 条：小程序端单次查询上限是 20，现已分页取）。
- **新页面「这一餐」**（`pages/meal/meal`）：列出这位参与者这一天这一餐的全部菜品（按编号和当天时间查，不受 60 条限制），每道菜可点进识别详情，或直接「去评估 / 修改评估」，长按可删除。底部按钮按状态变化：
  - 还没点「拍完了」时，显示「拍完了，开始评估」；
  - 有待评估的菜时，显示「评估下一道」；
  - 全部评完后，显示「看这一天的汇总」。
- **评估后回到这一餐**：从「这一餐」进入的评估，完成后回到这一页，接着评下一道。从其他入口进入的评估，完成后照旧进入每日汇总。

分组依据：同一参与者编号、同一北京时间自然日（按 `createdAt`）、同一餐次（结果页选的 `mealType`，未选的旧记录归为「未选餐次」）。

## 3. 饭后评估：滑条 0–100%，超过一份用按钮或输入框

- 滑条只到 100%，拖到最右就是「吃完」，不识字的老人不会误拖到 500%。
- 0%、25%、50%、75%、100%、200%、500% 的快捷按钮保留。
- 新增「其他比例」输入框：只收 0–500 的整数，点键盘「完成」或离开输入框即生效，超范围会提示。
- 比例超过 100% 时，滑条停在最右，并提示「已选 250%，比拍照时的份量多」。

数据保存规则不变（0–500%，逐项确认）。

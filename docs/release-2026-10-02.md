# 2026.10.2：饭后评估对应参与者编号

同一部手机可为不同老人拍菜。每条识别使用拍照前填写的参与者编号，历史列表、识别结果、记录详情及饭后评估都显示这个原始编号（ID）。评估页同时展示原照片，提交区域再次显示编号，方便确认评估对象。

## 使用方式

1. 为第一位老人拍照前填写其编号，例如 `001207`。
2. 为另一位老人拍照前更换为其编号，例如 `000008`。
3. 全部菜拍好后点“拍完了”。饭后进入“历史记录”，按编号找到对应菜品，逐道填写评估。

编号始终保留为文本，包括前导零。手机当前保存的编号仅供下一次拍照使用，不能覆盖已经拍过的菜或它的评估。无需在评估页重新输入编号。

## 数据关联

| 字段 | 含义 |
| --- | --- |
| `participantCode` | 菜品拍照时填写的参与者编号快照 |
| `analysisId`（云文档 `_id`） | 唯一的菜品识别记录 ID |
| `consumption.participantCode` | 每次保存评估时从该菜品快照取得的编号 |
| `consumption.analysisId` | 本次评估对应的菜品记录 ID |

本机评估草稿仍按菜品记录 ID 分开保存；云端草稿、完成评估、修改已完成评估及删除食材后的重算都沿用该菜品身份。两位参与者可共用一顿饭的拍摄会话，每道菜的评估独立。

已有菜品记录中保存过编号的，更新后会直接显示原编号。旧记录缺少编号时显示“未记录编号”，保留照片供人工确认，不套用手机当前编号。既有评估在下一次保存时写入新增身份字段，原始记录的关联不变。

本次仅涉及小程序前端及共用评估构建逻辑，无需重新部署识别云函数。后台导出已包含主记录的参与者编号及记录 ID，继续使用原导出工具即可。

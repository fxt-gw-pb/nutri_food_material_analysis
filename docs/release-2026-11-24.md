依据 `1124/小程序第3阶段开发思路.docx`，本次只做第 1、3 点：

1. 每顿饭、每天的**质量加权 TPA 切割质构系数**；
3. 每顿饭、每天的**营养素摄入量**（依据《中国食物成分表标准版（第 6 版）》）。

## 用户能看到什么

| 位置 | 内容 |

## 计算口径

### 质构（与 `1124/切割质构系数_质量加权计算说明.pdf` 一致）

```
加权质构系数 = Σ(各食物摄入质量 × 切割实验质构参数) ÷ Σ(各食物摄入质量)
```

- 摄入质量 = 饭后评估比例 × 拍照估重，即记录中的 `consumption.consumedGrams`（对应 Excel 的 U 列）；
- 只用**切割测试**读数。匹配到的是下压测试记录时，取同菜、同食材、同烹饪方式的切割那一条；没有切割数据的食材不进入切割系数；
- **缺失值不当作 0，分母也排除其质量**，8 项指标（硬度、脆度、黏着性、弹性、咀嚼性、胶着性、内聚性、回复性）各自计算分母；样品高度不加权；
- **单餐** = 同一参与者、同一天、同一餐次（早餐/午餐…）的全部菜；**全天** = 当天所有餐次的食物合在一起重新加权，**不是**各餐结果的平均；
- 「一天」按北京时间（UTC+08:00）自然日，以拍照时间 `createdAt` 为准，与手机时区无关；
- 只计入已完成饭后评估（`evaluationStatus=completed`）的菜。

页面上的硬度档位（很软/偏软/适中/偏硬/很硬）沿用质构库原有的分位数阈值。

### 营养

```
某营养素摄入量 = 摄入质量 × 折算系数 × 每 100 g 可食部含量 ÷ 100
```

- 数据：第一册（植物性食物）、第二册（动物性食物）的「表一 能量和食物一般营养成分」，共 1642 种食物、22 项营养素（能量、蛋白质、脂肪、碳水化合物、不溶性膳食纤维、胆固醇、维生素 A/B1/B2/C/E、烟酸、钙、磷、钾、钠、镁、铁、锌、硒、铜、锰）。未收婴幼儿食品和「其他」（药食两用）两类；
- 原书印「—」（未检测）的营养素不当作 0，只是不累加，页面在该项后加 `*` 并注明合计偏低；
- **食材 → 成分表食物**的匹配见 `miniprogram/services/nutritionMatch.ts`：先查常用食材对照表（逐条人工指定编码，覆盖历史记录里出现过的绝大多数食材），再按成分表主名/别名、去掉刀工后缀和状态前缀、名字包含关系依次匹配，并核对肉的种类不冲突；最后只认出类别时（某种菇、某种鱼、某种猪肉）按该类代表食物近似。调料、汤汁和饺子、包子、面包这类成品在第一、二册里没有，**不计入，也不拿相近食物硬凑**；
- 两处折算（页面与导出都写明原因）：
  - **带骨、带壳**的肉禽鱼虾：估重包含骨头和壳，按成分表「食部」折成可食部（如排骨 70%、整条草鱼 58%）。肉丝、肉片、虾仁、鱼片等不折；
  - **按干品收录**的粉丝、粉条、米粉、腐竹、银耳、莲子：盘里是泡发或煮过的，按吸水倍数折回干重（如粉丝 ×0.3）；
- 主食优先用成分表的熟制品条目（米饭（蒸）、面条（煮）、米粥、馒头）。其余食材多为生重数据，**烹调中的水分变化与用油、用盐未计入**，结果用于饮食记录参考。

## 数据如何存

完成评估时，`consumption.intake` 另存一份按当时算法算出的结果，供后台查询导出：

| 字段 | 含义 |
| --- | --- |
| `algorithmVersion` | `intake-2026-11-24` |
| `consumedG` | 已评估食材摄入总质量（g） |
| `textureSums.<指标>.weightedSum / grams` | Σ(摄入质量 × 指标值) 与参与计算的质量。多道菜直接相加后再相除，就是整餐、全天的加权值 |
| `nutrients.<营养素>` | 实际摄入量，单位见 `NUTRIENTS`（能量 kcal、蛋白质 g、钠 mg、硒 μg…） |
| `nutritionG` | 对上成分表的摄入质量（g） |
| `ingredients[]` | 逐食材：摄入克数、切割记录 id、成分表编码与名称 |

小程序页面不读这份快照，始终按当前算法重算，旧记录（没有 `intake`）同样能显示。已评估过的旧记录不会被自动补写；重新打开评估并点「完成评估」会补上。

每日汇总读取的是本手机微信账号创建的记录（`meal_records` 权限为仅创建者可读写）：同一位老人在两台手机上拍的菜，各自只汇总本机那部分。查询条件为 `participantCode + status + createdAt` 范围；数据量变大后可在云开发控制台为 `meal_records` 建 `participantCode` 升序 + `createdAt` 升序的组合索引。

## 成分表数据的来源与版权

`1124/` 下的两册 PDF 是扫描图片，没有文字层。`scripts/nutrition/` 用 macOS 自带的 Vision 文字识别在本机做了两遍独立识别（300 dpi、400 dpi），逐格互相校对：

- 两遍一致的直接采用（约 4.3 万格）；不一致的按该列印刷格式（小数位数）判断哪遍丢了小数点；
- 用「水分 + 蛋白质 + 脂肪 + 碳水 + 灰分 ≈ 100 g」和能量折算两条物理约束逐行检查，仍可疑的对照扫描页逐格人工核对，更正写在 `finalize_table.py` 的 `MANUAL`；
- 原书「野菜」一节 kcal 与 kJ 两列印反，已按 kJ ≥ kcal 摆正。

产物 `scripts/source/中国食物成分表第6版_表一.csv`（可直接用 Excel 打开核对）与 `miniprogram/data/nutritionDb.data.ts`。原书版权页注明「未经所有者应允，任何形式出版和大量转用等商业行为（如书籍、电子版、软件、网络媒体等）均视侵权，公益活动营养教育使用除外」，且仓库为公开仓库，所以**这两个文件和 PDF 都只留在本机（已加入 `.gitignore`）**。换电脑时：

```bash
scripts/nutrition/extract.sh 1124/中国食物成分表标准版第6版第一册（2018）(1).pdf 1124/中国食物成分表标准版第6版第二册（2019）(1).pdf
python3 scripts/build-nutrition-db.py
```

新克隆的仓库没有这两个文件时，`npm run type-check` 和营养相关测试会因找不到 `nutritionDb.data.ts` 而失败，先执行上面两步即可。

# 2026-09-28 视觉模型升级与校准验证

## 已上线

线上模型为固定快照 **qwen3.8-max-0902**。小程序实际调用已确认请求与返回模型一致；接入版本为 `2026-09-28-vision-proxy-calibration-v1`，提示词为 `qwen-dish-visible-food-weight-v8`。只更新云函数，无需重新发布小程序前端。

选型依据为阿里云官方的[视觉模型指南](https://help.aliyun.com/zh/model-studio/vision-model)及[固定快照说明](https://help.aliyun.com/zh/model-studio/qwen3-8-max)。这不意味着任何菜品都能无误识别。

## 校准参照及方法

用户明确同意以旧版完成肉类减半后的数值作为大约估计的实际值。实际采用原记录的 `auditSnapshot.totalG`，已扣除被删除的食材；排除 7 条作废记录，留下 **21 条保留记录、16 组菜品/拍摄场景**。这是用户认可的旧算法代理参照，**不是实称重量**。

先在每组计算新旧估重比值的对数中位数，再对场景组等权取中位数，得到新模型份量系数 **1.9**。这样避免重复拍摄的某一道菜主导系数。校准只对新模型生效，原肉类 **0.5** 校正继续在前端执行一次。

校准在云端同步缩放估重所用体积及模型直接克数，保持既有加权几何平均的计算关系。为兼容现有前端，`result.dish` 保存用于估重的校准后有效面积、厚度和克数；原始模型输出保留在 `modelAudit.rawDish`，系数和参照类型保留在 `modelAudit.quantityCalibration`。原始预测不会被覆盖。超出既有几何范围时拒绝保存，不静默截小。

## 留组验证

每次留出一整个菜品/拍摄场景，只用其余组拟合系数，然后验证留出组；同一道菜的重复照片没有同时用于该折的拟合与验证。

| 相对旧版代理参照的指标 | 未校准 | 留组验证 | 全部参照拟合后的记录内结果 |
|---|---:|---:|---:|
| 中位绝对相对偏差 | 51.7% | 31.8% | 18.2% |
| 平均绝对偏差 g | 163.2 | 104.7 | 81.6 |
| 偏差在 30% 内 | 1/21 | 10/21 | 12/21 |
| 偏差在 50% 内 | 10/21 | 15/21 | 16/21 |

留组验证更适合评估对新场景的适用性，记录内结果不能当作独立验证。仍有部分样本偏差较大；以上指标衡量与旧版数值的接近程度，不能作为实称准确率。

## 功能与线上验证

- **66 项测试通过**，TypeScript 类型检查通过。
- **28 张历史测试照片**全部得到合法且非空的食物结果，其中 1 张复核一次；模型调用最慢 **34.045 秒**。这些照片包含重复拍摄与屏幕照片，不是 28 道独立的已称重菜品。
- 无食物对照正确返回 `dish:null`，不会为了给出结果而编造食材。
- 线上通过真实小程序 API 完成了鸡蛋与肉丝两项 `create → process → 读结果` 测试。确认新模型、v8 提示词、1.9 系数、原始预测和校准参数均正确；模型处理分别耗时 13.476 秒、14.371 秒。
- 两条本次新建的测试记录均已删除，未删除原照片，也未修改参与者记录。
- 使用线上返回数据验证前端估重、100% 食用比例和审计快照，合计一致；肉类减半只执行一次。
- 对 69 条历史单道菜结果、228 项食材回放，既有归一化与前端计算结果无差异。重量、质构匹配、饭后评估三个前端算法文件与修改前备份字节一致。

## 输出与质控变化

v8 提示词要求依据可见食物，成型主食保留馒头等成品名称，减少拆成面粉、酵母、水的情况。无法确定品种与没有食物分开处理，不确定品种给低置信度。

新模型使用 512 token 推理预算、JSON 输出和最多一次同模型复核，整个模型调用受 50 秒总预算约束。保留现有云函数 60 秒及前端 90 秒限制。仅修复已知 JSON 字段中无意义的空白；字段冲突、无效数值和异常面积合计会报错，不伪装成成功。

原肉类减半、经验密度、几何与直接估重融合、重量区间、逐食材匹配、最长烹饪时间、切割/下压双读数、人工改选、食材删除及 0%–500% 饭后评估均保留。已完成或作废的历史记录不会因普通重复处理被新模型重算。

## 研究导出口径

`area_ratio`、`height_cm`、`model_estimated_g` 为校准前模型预测；新增 `effective_*` 列为实际送入前端估重的校准后参数。`quantity_calibration_version`、`quantity_calibration_factor`、`calibration_reference_type` 用于区分不同口径。完整导出的 `raw_modelAudit` 保留整份原始预测与校准信息。旧记录的原数值不会被导出脚本覆盖。

## 已知限制

没有实称数据与逐项人工标签，不能保证每份菜的真实克数或食材名称都准确。部分模糊、小份食物仍有品种分歧，需要人工核对。测评材料中的花生仁/花生芽误匹配属于已有的本地名称匹配问题，本次没有改动该规则，仍需单独修复。

后续说明（2026-09-29）：上述限制描述的是 9 月 28 日已部署版本。花生仁/花生芽及其他标黄匹配已在本地代码修正，复核结论见 [9 月 28 日匹配复核](../0928反馈/匹配复核结论.md)；用户端需发布新版小程序后才会采用新规则。

## 部署及回退

当前函数已通过官方微信开发者工具 CLI 以 4 个源码文件部署，使用云端安装依赖。此前的本地依赖打包及 Updating 状态问题已处理，最终部署返回 success:true，随后线上调用验证成功。

回退可将云函数环境变量 `QWEN_MODEL` 设为 `qwen-vl-max`，会沿用旧 v5 提示词并跳过新模型的份量校准；需要完全还原时使用 `exports/vision-upgrade-20260928/predeploy-backup`。密钥仍仅在云函数环境变量中，未写入项目。所有模型、提示词与校准版本都会随新记录保存。

验证明细位于 `exports/vision-upgrade-20260928`。可复算校准：

```bash
node scripts/vision/calibrate.cjs exports/vision-upgrade-20260928/live/proxy-references-kept.json exports/vision-upgrade-20260928/live/v8-final-validation/results.json exports/vision-upgrade-20260928/live/scene-groups-kept.json exports/vision-upgrade-20260928/live/proxy-calibration-validation-kept.json
```

复算必须使用原始预测 `rawDish` 或未校准的 `dish`，不能再次使用已校准参数。后续有实称数据时，应建立新的校准版本并重新做留组验证。

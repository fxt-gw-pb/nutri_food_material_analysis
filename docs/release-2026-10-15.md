# 2026.10.15 随访问卷

首页新增“每周随访”和“问卷记录”。问卷采用 `1015新增问卷/小程序随访表(1).docx` 中的六道题和全部原始选项。按已确认的需求，随时可填，每次新填写单独保存，不设置每周次数限制。

## 填写流程

1. 首页填写参与者编号，点击“填写随访问卷”。编号按文本保存，保留前导零。
2. 根据最近一周的情况作答。第 1–5 题单选，第 6 题多选；“都没有”与其他选项互斥。没有默认答案，六题均必填。
3. 每次选择后在手机上保存草稿，按参与者、问卷版本和环境隔离。退出后重新进入可继续。
4. 提交后显示该次编号、提交时间及原答案。问卷记录按当前微信账号和所选参与者查询，分页加载，可查看以往提交。

表单打开后固定本次参与者编号，手机当前编号改变不会改写这份问卷。查看历史使用该条记录的原编号、题目及选项文字快照。换人填写须回首页更换编号。问卷不依赖拍照或饭后评估。

提交前会先在手机上保存提交编号和完整答案。网络超时或服务不可用时，答案保持锁定，点击“重试提交”沿用原提交编号；云端只插入一次，保留首次提交时间。确认成功后才能开始下一份。原文没有给出计分规则，本版仅记录原始回答，不生成总分或诊断。

## 云端部署

新增的资源必须先部署，再上传小程序；仅修改本地文件不会让线上出现问卷。

1. 在生产环境 `cloud1-d8gfgeids7d390dbc` 创建集合 `questionnaire_responses`，权限设为 **仅管理员可读写**（`ADMINONLY`，自定义规则等价为 `{"read":false,"write":false}`）。前端通过云函数读写，不开放客户端直接写入。
2. 给集合建立普通复合索引：`_openid` 升序、`participantCode` 升序、`createdAt` 降序、`_id` 降序，用于分用户、分参与者的时间倒序历史查询。
3. 微信开发者工具右键 `cloudfunctions/questionnaire` →“上传并部署：云端安装依赖”。需包含 `index.js`、`handler.js`、`schema.json`、`package.json`；依赖 `wx-server-sdk`。建议超时 20 秒，无需 API Key。
4. 保持 `miniprogram/services/config.ts` 的 `useCloud: true` 和 `questionnaireFunctionName: 'questionnaire'`。识别云函数 `analyzeMeal` 无需重新部署。
5. 运行 `npm run type-check`、`npm test`，在开发者工具中验证填写、提交与历史查询。联网验证使用明确的测试编号，并在后台区分测试记录。
6. 上传小程序版本 `2026.10.15`，先在体验版验收，再按既有流程审核发布。

集合权限参考腾讯云[安全规则](https://docs.cloudbase.net/database/security-rules)。云函数具有管理员权限，因此每次请求都从 `getWXContext().OPENID` 取得当前身份；列表和详情查询显式限制 `_openid`，不信任客户端传入的身份、时间或题目快照。

## 数据字段

问卷独立存入 `questionnaire_responses`，不写入 `meal_records`，不改变每日新增识别统计、饭后评估或原数据导出。

| 字段 | 含义 |
| --- | --- |
| `_id` / 前端 `responseId` | 问卷记录 ID，由微信身份和提交编号计算；重复请求不会新增 |
| `_openid` | 实际提交者的微信身份，由云函数取得 |
| `participantCode` | 本次参与者编号快照，文本，保留前导零 |
| `submissionId` | 一次填写的提交编号；网络重试保持不变 |
| `questionnaireVersion` | 本版为 `2026-10-15-v1` |
| `title`、`recallPeriod` | 问卷名称与回顾期“最近一周” |
| `answers.q1` 至 `answers.q6` | 选项编码数组；前五题各一个，第六题一个或多个 |
| `answerItems` | 六题各自的题干、选项编码、中文答案快照，便于导出和回溯 |
| `createdAt` | 云函数生成的提交时间，Unix 毫秒；页面统一显示 UTC+08:00 |

可在云后台单独导出 `questionnaire_responses` 的 JSON。现有 `export:data` 等命令面向菜品记录，不能直接用于问卷。跨手机或不同微信账号的同编号记录由管理员在后台汇总；小程序只显示当前微信账号提交的记录。

## 本地验证与维护

`useCloud: false` 可体验本机演示保存、历史与分页，页面明确显示演示模式；演示数据及草稿与云端隔离。云端失败不会自动降级成本地提交成功。

```bash
npm run type-check
npm test
```

问卷专项测试覆盖：无默认答案、必填和互斥、原文配置与服务器快照一致、前导零与换人隔离、草稿恢复、存储失败、连点防重、超时重开后重试、并发提交、服务端校验、身份越权拦截、分页、历史快照以及失败提示。

题目定义位于 `miniprogram/data/questionnaire.ts`，部署用定义位于 `cloudfunctions/questionnaire/schema.json`。以后修改题目必须同步两处并升级版本，历史详情始终显示原快照，不按新题目重新解释旧数据。
